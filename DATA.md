# Data provenance

This document records, for every data file shipped or referenced in this
repository, what it is, which figure reads it, and how the corresponding *raw*
(large) `.mat` is regenerated from the MATLAB pipeline.

## Two tiers of data

1. **Committed lightweight data** — `plotting/data/code_mirror/` and
   `plotting/data/ftle_comparison.mat`. These are the only data files needed to
   reproduce the paper figures. They total ≈ 34 MB. They were produced by
   `plotting/data/extract_figure_data.py`, which loads each raw `.mat` and keeps
   only the variables / slices the figure code reads. Re-running that script
   requires the original large files (tier 2) and is **not** required to
   reproduce the figures.

2. **Raw (large) pipeline outputs** — NOT committed (each is 0.1–1.2 GB; total
   ≈ 12 GB). They are regenerated by the `code/asy/` MATLAB pipeline. The table
   below maps each raw file to the script that produces it.

## Regenerating the raw files

Run the asymmetric pipeline under `code/asy/<sys>/` in this order (see
`code/asy/README.md` for details):

1. `gen_lorenz_data.m` (Lorenz) / the equivalent for Chen, quasi — generate the
   target trajectory.
2. `opt_chua_no_para.m` — hyper-parameter optimization (`surrogateopt`).
   - **Known manual step:** this script writes `opt_Logi_<timestamp>.mat`;
     downstream scripts load `opt_data_testnum_10.mat`. Rename/copy the
     optimizer output to `opt_data_testnum_10.mat` (and the matching
     `min_rng_set_testnum_10.mat`) before continuing.
3. `scan_rho.m` → produces `data_*_asy_*.mat` (the ρ-scan + SETI ingredients).
4. `{auto,driven,closed}_RC/RC_theory_{regime}.m` → produce `RC_data_*.mat`.

Then point the figure scripts at the regenerated tree:

```bash
export SETI_CODE_BASE=/path/to/your/code
cd plotting && python3 run_all.py
```

## Why the large files are not committed

GitHub's per-file size limit (100 MB) is exceeded by several raw outputs, and
the full raw set (~12 GB) is far beyond reasonable repository size. Because
every raw file is reproducible from the shipped `code/asy/` pipeline, and every
figure is reproducible from the committed lightweight data, no information is
lost.
